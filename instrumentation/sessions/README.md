
# Session Instrumentation

Out of the box, the `opentelemetry-android` agent will create and manage sessions. Sessions are associated
with a unique identifier and will expire after a duration. This instrumentation is responsible
for adding a `SessionObserver` instance that will generate OpenTelemetry events for
`session.start` and `session.end` when interesting things happen to the session.

See [session.md in the semantic conventions](https://github.com/open-telemetry/semantic-conventions/blob/main/docs/general/session.md)
for additional details about sessions.

See ["Session Events"](https://github.com/open-telemetry/semantic-conventions/blob/main/docs/general/session.md#session-events)
for more information about the specific events generated by this instrumentation.

## Configuration

When using the [android agent](../../android-agent), sessions work out of the box with sensible defaults.
You can customize session behavior using the configuration DSL:

```kotlin
OpenTelemetryRumInitializer.initialize(context) {
    session {
        // Session expires after 15 minutes in background (default)
        backgroundInactivityTimeout = 15.minutes

        // Session expires after 4 hours regardless of activity (default)
        maxLifetime = 4.hours
    }
}
```

To replace the default session manager, set a custom [SessionProvider](../../session/src/main/kotlin/io/opentelemetry/android/session/SessionProvider.kt) through the public [SessionConfiguration](../../android-agent/src/main/kotlin/io/opentelemetry/android/agent/dsl/SessionConfiguration.kt) DSL:

```kotlin
OpenTelemetryRumInitializer.initialize(context) {
    session {
        sessionProvider = SessionProvider { "my-session-id" }
    }
}
```

This replaces default session generation and timeout handling, so the timeout settings above no longer apply.
The plain `SessionProvider` in this example does not emit `session.start` or `session.end` events.
To emit those events, the provider must also implement [SessionPublisher](../../session/src/main/kotlin/io/opentelemetry/android/session/SessionPublisher.kt) and notify its observers of session changes.

## Installation

This instrumentation comes with the [android agent](../../android-agent) out of the box, so
if you depend on it, you don't need to do anything else to install this instrumentation.
However, if you don't use the agent but instead depend on [core](../../core) directly, you can
manually install this instrumentation by following the steps below.

### Adding dependencies

```kotlin
implementation("io.opentelemetry.android.instrumentation:sessions:1.8.1-alpha")
```

1. You can find the latest version [here](https://central.sonatype.com/artifact/io.opentelemetry.android.instrumentation/sessions).
